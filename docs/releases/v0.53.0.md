# StudyOS v0.53.0 — Desktop Upgrade Safety

**This release is about one thing: existing StudyOS desktop data should survive upgrades cleanly.**

v0.53.0 hardens the Windows desktop upgrade path after the institutional-course and automatic-update work shipped in v0.52.0.

## What changed

### Legacy desktop databases now migrate on startup

Older StudyOS desktop builds created local SQLite databases before the current institutional catalog and admin schema existed.

v0.53.0 now runs the bundled Alembic migration chain before the local FastAPI backend starts serving requests.

That means an existing user can install or auto-update to a newer StudyOS build without manually deleting or rebuilding their local database.

### Migration scripts are included in the packaged backend

The Windows backend sidecar now ships the Alembic migration resources it needs at runtime.

The launcher resolves those migrations from the packaged PyInstaller environment and upgrades the database to the current schema before starting Uvicorn.

### Real legacy-upgrade release test

The Windows release workflow now creates a deliberately old StudyOS SQLite database, launches the **actual bundled backend executable**, waits for readiness, and verifies that:

- the database receives an Alembic revision;
- `users.is_admin` exists;
- the institutional `catalog_courses` table exists;
- the source-discovery `catalog_sources` table exists.

If that upgrade path fails, the Windows release build fails.

### Web runtime security update

StudyOS now ships Next.js 15.5.24, the current patched Maintenance-LTS release for the 15.5 line as of the v0.53 release audit.

This replaces the vulnerable 15.5.0 runtime previously used by the web and bundled desktop shell.

## Existing v0.52 users

v0.52.0 already introduced the automatic updater.

For installed v0.52.x builds, v0.53.0 can be delivered through the normal StudyOS updater once the release is published.

Portable builds remain manual-download only.

## Windows release validation

v0.53.0 continues to require the packaged Windows application to pass:

- bundled backend build;
- legacy database migration smoke;
- fresh database backend smoke;
- Next.js production build;
- packaged runtime verification;
- NSIS installer build;
- updater metadata + blockmap validation;
- actual packaged StudyOS startup;
- real registration/authenticated API traffic through the desktop proxy.

## SmartScreen

StudyOS beta binaries may still be unsigned. Windows can therefore show an **Unknown publisher** or **Windows protected your PC** warning until trusted code signing is configured.

## Release character

This is intentionally a smaller release than v0.52.0.

There are no major new study features in v0.53.0. The goal is to make upgrading the desktop beta safer before continuing feature work.
