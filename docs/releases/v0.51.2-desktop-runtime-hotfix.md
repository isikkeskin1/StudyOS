# StudyOS v0.51.2 — Desktop Runtime Hotfix

v0.51.2 fixes a post-release desktop reliability issue discovered in v0.51.1 where the
StudyOS UI could start successfully and later display "StudyOS server is unavailable".

## Fixed

- Desktop diagnostics now use a deterministic Windows location:
  `%APPDATA%\StudyOS\logs\desktop.log`.
- Recovery UI can open the diagnostics folder directly.
- Windows packaging now verifies the complete Next.js runtime inside the final app.
- The installed StudyOS payload is launched in CI after packaging.
- CI now sends real API traffic through the same local desktop proxy used by the UI:
  readiness, account registration, and authenticated account lookup.
- Partial desktop child processes are cleaned before recovery/retry.
- Hosted backend URLs are validated before being persisted.
- Backend packaging uses PyInstaller onedir to avoid repeated one-file extraction on every
  installed-app launch.
- v0.51.2 corrects the desktop package/release version mismatch that caused v0.51.1 release
  assets to retain 0.51.0 filenames.

## Release gate

Do not publish v0.51.2 unless the Desktop Windows workflow is green through:

1. bundled backend build
2. bundled backend readiness smoke
3. production web build
4. packaged Next runtime verification
5. installed StudyOS payload startup
6. proxy readiness request
7. proxy registration request
8. authenticated proxy request
9. Windows artifact upload
