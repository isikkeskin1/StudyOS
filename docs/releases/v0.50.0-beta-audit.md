## Security / production hardening

- SQLite foreign-key enforcement is enabled for development/test parity.
- User-owned course and semester data remains tenant-scoped.
- Account export excludes password hashes, session tokens, and internal storage paths.
- Account deletion requires password confirmation plus literal `DELETE`.
- Authentication attempts are bounded and return HTTP 429 with `Retry-After`.
- Unknown-user login paths still perform password-hash verification to reduce timing leaks.
- Expired/invalid session cookies are cleared.
- API responses use no-sniff, frame denial, referrer policy, permissions policy, no-store,
  and production HSTS.
- Web responses use CSP plus the same browser hardening headers.
- Production Compose requires an explicit Postgres password.
- Generic production startup trusts forwarded headers only from configured proxy addresses.
- Containers run as non-root application users.
- Readiness checks both database connectivity and writable upload storage.

## Known beta limitations

- Auth rate limiting is process-local. It is appropriate for the current single API process
  deployment, but a distributed/shared limiter should replace it before horizontally scaled
  multi-worker production.
- CSP still permits `unsafe-inline` for Next.js bootstrapping/styles. `unsafe-eval` is
  disabled in production.
- JSON account export intentionally does not package original uploaded source files.
- OpenAI-dependent features require valid provider configuration; standard CI does not
  require external provider credentials.
- Git tagging/release publication is not performed by application CI.
