# StudyOS v0.55.0 — The Workspace Revamp

v0.55.0 is the release where StudyOS stops feeling like a collection of study features and starts feeling like one place to actually work.

The academic engine underneath StudyOS is still the same evidence-driven system: course material, diagnostics, mastery, mistakes, forecasts, planning and reviews. What changed is the surface above it. The product now puts the next useful action first, keeps context close, and removes a lot of the dashboard chrome that made serious study data feel like generic SaaS analytics.

## 🧭 A new Study Cockpit

The old overview has been replaced with a Today-first workspace.

- **One dominant next session** instead of a wall of competing cards.
- Live focus state with start, complete and skip controls.
- Expected mark gain and planned duration stay attached to the work itself.
- **Course Momentum** is now a dense academic ledger showing estimate, target, evidence, mastery, focus time and exam pressure in one row.
- A compact **Study Rhythm** timeline shows focused minutes without turning activity into a vanity metric.
- The **Review Queue** surfaces mistake burden and repeated weak points directly from student evidence.
- A persistent context rail keeps the current study block, current-window performance, nearest exam, plan progress and optional music within reach.

The result is intentionally quieter: fewer decorative cards, fewer rounded containers, less filler copy and more information that changes what the student should do next.

## 📚 Course workspaces became real workbenches

Course pages now use the same v0.55 visual language as the semester cockpit.

The sidebar is quieter, headers are more editorial, metrics sit in flat evidence strips, and topic/source lists behave like ledgers instead of cards. Tutor, diagnostic, practice, mistakes, forecast and cheat-sheet surfaces were restyled without removing their existing functionality.

The important part is continuity: moving from the semester view into Physics or Programming should no longer feel like opening a different application.

## 🎧 Spotify, if you want it

StudyOS now supports an **optional Spotify account connection**.

After connecting Spotify, StudyOS can show:

- the current track and artists
- album artwork
- the active Spotify device
- playback progress
- previous / play-pause / next controls when the Spotify account is eligible

The player lives in the semester context rail and can follow a connected user into a course workspace as a small collapsible study player. Users who do not connect Spotify never need to interact with it.

Connection management lives in **Account & integrations**, so music does not become another mandatory onboarding step.

### Desktop pairing

The Windows app opens Spotify authorization in the system browser and then securely waits for the account link to complete. Desktop pairing no longer assumes the user can finish the Spotify login flow within a few seconds; StudyOS polls the centralized account for up to two minutes.

## 🔐 Spotify privacy and account safety

Spotify is implemented as a server-side integration rather than a browser token hack.

- OAuth access and refresh tokens are **encrypted at rest**.
- The encryption secret and Spotify client secret stay on the hosted backend.
- The Electron/Windows package never receives the Spotify client secret.
- OAuth uses short-lived, one-time state attached to the correct StudyOS account.
- Users can disconnect Spotify at any time.
- Spotify credentials and temporary OAuth state are explicitly excluded from account JSON exports and local-to-cloud migration ZIPs.
- Token refresh happens server-side.

The OAuth callback can be reached without an existing browser session so desktop pairing works, but it cannot attach a connection without a valid one-time state generated by an authenticated StudyOS account.

## 🧰 The rest of the product caught up

A full revamp cannot stop at the home screen. v0.55 also brings the same visual system to:

- first-run course setup
- course management and material ingestion
- institutional catalog administration
- global search
- account/session/data settings
- sign in, registration, email verification and password recovery

The supporting surfaces now use flatter panels, restrained borders, denser typography and consistent controls rather than reverting to the old card-heavy style whenever a modal opens.

## 🧱 Integration and deployment work

The Spotify database migration is upgrade-safe for both existing databases and clean installs. Compose deployments can now receive the integration secret, Spotify client credentials and redirect URI through environment variables, and v0.55 aligns backend, web, desktop and PWA release metadata.

The integration remains **off by default**. StudyOS simply hides Spotify surfaces when the provider has not been configured.

## What v0.55 is really about

StudyOS already knew a lot about the student. The problem was that the interface still made the student hunt through that intelligence.

v0.55 changes the relationship:

> **StudyOS should feel less like analytics you inspect and more like a workspace that is already pointing at the right piece of work.**

That is the direction of the product from here.
